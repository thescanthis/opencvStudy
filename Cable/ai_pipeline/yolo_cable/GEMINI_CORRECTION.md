# 제미나이 교정 지시문 — 라벨링 좌표 정확도

## 현재 문제

방금 만든 라벨 8장(`make_labels_batch1/3/4.py` → `labels/all/*.txt`)을 도면과
대조한 결과, **박스가 실제 객체와 크게 어긋난다.**

- `A50035007-6`: connector 2개 모두 빈 공간에 있음 (실제 P1/P2 위치와 전혀 안 맞음)
- `A60023103`: connector 8개 중 6개가 케이블 중간이나 빈 공간에 헛박스
- `A60023109`: branch_sleeve 는 얼추 맞으나 connector 절반이 빗나감
- 공통: dimension/balloon 이 실제 위치가 아니라 대략적으로 뿌려짐, 박스가 tight
  하지 않음

**원인**: 축소된 도면(장변 2000px)을 그대로 보고 좌표를 눈대중으로 찍었다.
커넥터는 작아서(50~80px) 이 방식으로는 정확히 못 찍는다.

**이 라벨로 학습하면 안 된다.** 잘못된 정답으로 배우면 모델이 망가진다.

## 올바른 방법 (반드시 이 순서대로)

### STEP 1 — 배선 그림 영역이 어디인지 파악

먼저 전체 도면을 그리드 없이 한 번 본다:
```bash
cd C:\AIND_Library\Git_PredicTest\x64_Cami_Lib\PSCD1500\PSCD1500\Cable\ai_pipeline\yolo_cable
python grid_view.py <도면명>          # 예: python grid_view.py A60023103
```
→ `preview/_grid_<name>.png` 생성. 이걸 보고 **케이블 배선 그림이 이미지의
어느 영역(x범위, y범위)에 있는지** 대략 파악한다.
(보통 상단 좌측 60~75%. 하단은 배선도/부품표라 무시.)

### STEP 2 — 배선 영역만 3~4배 확대 + 그리드

```bash
python grid_view.py <도면명> x0=<좌> y0=<상> x1=<우> y1=<하> scale=<2.5~4>
```
예: 배선 그림이 대략 x 100~1500, y 300~800 에 있으면:
```bash
python grid_view.py A60023103 x0=100 y0=300 x1=1500 y1=800 scale=2.5
```
→ `preview/_grid_A60023103.png` 에 **빨간 그리드(100px 간격 + 좌표 숫자)** 가
그려진 확대 이미지.

**중요**: 그리드에 적힌 숫자는 **항상 원본 2000px 이미지의 좌표**다. 확대해도
숫자는 원본 기준. 이 숫자를 읽어서 박스 좌표(x1,y1,x2,y2)를 정한다.

### STEP 3 — 객체가 많거나 작으면 부분별로 더 확대

부채꼴(A60023110 등)이나 커넥터가 몰린 곳은 그 부분만 다시:
```bash
python grid_view.py A60023110 x0=1400 y0=300 x1=1700 y1=600 scale=5 step=50
```
(`step=50` 이면 50px 간격 그리드)

### STEP 4 — 좌표를 읽어서 박스 리스트 작성

그리드 이미지에서 각 객체의 **좌상단 (x1,y1)** 과 **우하단 (x2,y2)** 을 읽는다.
- connector: 플러그 몸통+커플링링+백셸의 외곽. 케이블 선은 제외.
- branch_sleeve: 몸통이 굵어진 마디 부분만.
- dimension: 숫자 텍스트만 타이트하게. 양끝 화살표·치수선·세로 보조선 전부 제외.
- balloon: 원 하나당 박스. 약 26~32px 크기.

```python
A60023103 = [
    ("connector", 155, 620, 240, 700),    # P1 - 그리드에서 읽은 실제 좌표
    ("connector", 1380, 560, 1460, 640),  # P2
    # ...
]
save_label("A60023103", A60023103)
```

### STEP 5 — 반드시 preview 검수

```bash
python make_labels_batch<N>.py
```
→ `preview/<name>_boxes.png` 가 생성된다. **이걸 반드시 열어서 확인:**
- 모든 박스가 실제 객체 위에 있는가?
- 박스가 객체에 딱 맞는가(너무 크거나 작지 않은가)?
- 빠진 커넥터/분기점은 없는가?

**어긋난 게 있으면 STEP 4 좌표를 고쳐서 다시 실행.** 검수 없이 다음 도면으로
넘어가지 말 것.

## 클래스 규칙 (재확인)

| 클래스 | 무엇 | 박스 |
|--------|------|------|
| `connector` | 케이블 **끝**의 플러그 (P1, P2...). 나사선/링/백셸. | 부품 외곽만. 케이블선 제외. 원형 핀배치 상세도(원+점들)는 **라벨 안 함** |
| `branch_sleeve` | 분기점의 **굵은 마디** 부품 | 굵어진 부분만 |
| `branch_bare` | 부품 **없이** 선만 갈라지는 분기점 (부채꼴 밑동) | 선 교차점 주변 작은 사각형 |
| `elbow` | 케이블 **중간**의 꺾임 부품 | 부품 외곽. 끝의 엘보는 connector |
| `dimension` | 치수 숫자 | 숫자 텍스트만 타이트하게. 화살표/치수선/세로 보조선 전부 제외 |
| `balloon` | 풍선번호 원 | 원마다 하나 |

### 절대 라벨 안 하는 것
- 하단 배선도(회로도), 부품 목록 표, 도면 테두리, 타이틀블록, 수정 이력 표,
  주기(注記) 문장, 척도 표시, 워터마크
- 커넥터 옆의 **원형 핀배치 상세도** (동그라미 안에 점들, `MS3475...` 표시)
- 케이블 형상과 무관한 모든 텍스트

## 참고: 왜 이렇게까지 하나

YOLO 는 우리가 준 박스를 "정답"으로 믿고 학습한다.
- 박스가 커넥터에서 100px 벗어나 있으면 → 모델이 "커넥터는 저 빈 공간에 있는
  것" 으로 배운다.
- 박스가 실제보다 크면 → "커넥터 = 큰 영역" 으로 배워서 나중에 정확한 위치를
  못 짚는다.
- 잘못 친 박스 1개가 제대로 친 박스 10개의 학습 효과를 깎는다.

라벨 정확도 = 모델 정확도. 도면 하나에 10분 더 쓰더라도 STEP 1~5 를 지킬 것.
