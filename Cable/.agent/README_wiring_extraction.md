# 배선도 영역 추출 + 텍스트 추출 파이프라인

`ai_pipeline/template_gui.py`(Tkinter GUI) — 케이블 도면 PDF 한 장(보통
"1.케이블 형상도 2.케이블 도면(배선도) 3.부품목록표"로 구성)에서 배선도
영역만 사람이 직접 골라내고, 그 안의 텍스트(핀 문자, 와이어 번호, 커넥터명
등)를 로컬 VLM(Gemma, LM Studio)으로 추출하는 독립 도구. `.agent/README.md`의
3D 시각화 파이프라인과는 별개 작업이며 서로 의존하지 않는다.

## 목적

케이블 도면 PDF는 벡터 데이터가 없는 통짜 스캔 이미지라(`.agent/README.md`의
"PDF는 스캔 이미지라 좌표를 자동 추출할 수 없다"와 같은 근본 제약), 도면
안의 텍스트를 얻으려면 OCR/VLM에 의존해야 한다. 이 도구는 그 과정을
반자동화한다 — 영역 선택만 사람이 하고, 텍스트 판독은 로컬 VLM이 한다.

## 핵심 결정과 시행착오

### 1. 자동 배선도 영역 검출(OCR 제목 찾기)은 포기, 수동 곡선으로 전환
"배선도/회로도/결선도"라는 제목 텍스트를 EasyOCR로 찾아 그 주변을 크롭하는
방식(`find_diagram_title`, `crop_diagram_region`, `find_diagram_quadrant` 등,
코드에 남아있음 - "자동 검출(참고용, 정확도 낮음)" 섹션)을 실측했으나:
- 64개 PDF 중 27개가 "제목 못 찾음"으로 실패 — 애초에 제목이 없는 도면,
  OCR이 "배선도"를 "버선도/비선도"로 오독하는 경우, 반대로 "배선공차"
  "회로번호 표시" 같은 무관한 문구를 오검출하는 경우가 뒤섞여 있었다.
- 내용물 밀도(잉크 공백 gap) 기반 섹션 자동 분할도 시도했으나, 도면마다
  신뢰도 편차가 커서(어떤 도면은 명확한 공백, 어떤 도면은 전혀 없음)
  일반화에 실패.
- 결론: **자동 검출은 참고용으로만 남기고, 실제 작업은 사람이 마우스로
  자유곡선을 그려 경계를 지정**하는 방식으로 전환(사용자 지시).

### 2. 크롭이 아니라 마스킹 — 그런데 미리보기는 크기에 맞춰 크롭
처음엔 "원본 페이지 크기/좌표계를 유지한 채 바깥을 흰색으로 마스킹"
(`mask_outside_region`/`mask_outside_polygon`)이 원칙이었으나, 실제로
결과 미리보기 패널에 이 원본 크기 그대로를 보여주면 배선도가 작게
찌그러져 보이는 문제가 있었다. 그래서 **미리보기/저장/이후 처리(Gemma
질의)는 경계의 바운딩박스로 실제 크롭한 이미지**를 쓰고, 페이지 전체
크기를 유지한 마스킹 버전은 좌표 참조가 필요한 벡터 추출용으로만
별도 보관한다(`self.masked_full_img`).

### 3. 구획선(직선)에서 자유곡선(폴리곤)으로
처음엔 가로/세로 직선을 그어 그리드 섹션으로 나누는 방식(`section_mode`)을
만들었으나, 실제 도면 경계는 삐뚤빼뚤하고 계단식으로 꺾인 모양(사용자
스크린샷 예시)이라 직선 그리드로는 못 따라갔다. **클릭으로 점을 찍어
자유곡선(폴리곤)을 그리고 `cv2.fillPoly`로 마스킹**하는 방식
(`mask_outside_polygon`, `finish_polyline`)으로 전환, 직선 구획선/드래그
크롭 기능은 완전히 제거했다(사용자 지시 - "자유곡선 한 개면 될 것 같다").

### 4. 벡터 PDF 추출은 구현했지만 대부분 무용지물
`extract_vector_region()`이 `page.get_drawings()`/`get_text()`로 벡터
좌표를 그대로 옮겨 새 PDF를 만드는 기능인데, 실측 결과 원본 PDF들
대부분이 `get_drawings()` count=0(벡터 정보 없음), `get_images()` count=1
(통짜 스캔)이라 벡터 추출이 의미가 없다(50073721, A60023104 등 확인).
기능은 남아있으나 실효성이 낮다는 점을 인지하고 있어야 한다.

### 5. VLM 텍스트 추출: "고정 개수 박스" 가정은 실제 도면에 안 맞는다
`ask_local_vlm_whole()`(기존, "N개 박스가 정해진 순서로 나열"을 가정)은
커넥터 핀 이름처럼 규칙적인 배열에만 맞고, 실제 배선도는 텍스트가 박스
안/밖/원(써클) 안에 제각각 놓여 있다(사용자 스크린샷 예시: P1 핀 문자,
와이어 번호 K-16, 신호명 SIG_LIMIT_ELE, 각주 번호가 뒤섞임). 그래서
레이아웃 가정이 없는 `ask_local_vlm_extract_all_text()`를 새로 만들어
"보이는 모든 텍스트를 위치와 함께 JSON으로 나열"만 요청한다. 연결관계
(넷리스트) 추론은 이 단계의 책임이 아니다(사용자 지시 - 텍스트만 필요,
좌표 근접도로 묶는 건 이후 별도 단계).

### 6. 전체 이미지를 한 번에 보내면 reasoning이 폭주한다
Gemma(QAT)는 LM Studio UI에 reasoning을 끄는 토글이 없고(실측 확인),
`/nothink` 프롬프트 접두사나 `chat_template_kwargs: {enable_thinking:
false}`도 이 모델/서버 조합에는 먹히지 않았다(실측). 도면 전체를 한 번에
보내면 핀 개수를 세다가("28개 핀인데 26개만 셌다" 같은) 같은 문장을
반복하며 max_tokens(6000)를 전부 소진하고 `finish_reason=length`로
끊겨 JSON 답변까지 못 감. 반면 **커넥터 하나 크기(가로/세로 약 900px대)
타일로 잘라 질의하면 reasoning이 3000토큰대로 끝나고 성공**한다(실측:
23개 항목, reasoning 3355토큰 vs 실패한 100+ 항목 시도).

→ **결론: 통짜 요청 대신 이미지를 자동으로 격자 타일로 나눠 개별 질의**
(`extract_all_text_tiled`). 타일 경계에서 텍스트가 잘리지 않도록 10%
겹침을 두고, 겹친 영역에서 같은 텍스트가 중복 추출되면 (text, 좌표 근접)
기준으로 제거한다.

### 7. 병렬 요청은 Context Length를 슬롯 수만큼 나눠 쓴다
타일을 병렬로(`ThreadPoolExecutor`) 동시 질의하면 벽시계 시간이 단축될
것 같지만, LM Studio는 **로드된 모델의 Context Length를 동시 요청 수만큼
쪼개 쓴다**. 실측: Context=2048, 4개 동시 요청 시 전부 "Context size has
been exceeded"로 실패. RTX 5080 16GB처럼 GPU 자원 자체는 충분해도, 이
설정값 때문에 병렬이 무의미해질 수 있다(하드웨어가 아니라 소프트웨어
설정 문제).

→ `compute_safe_parallelism(context_length)`로 "Context Length ÷ 요청당
예상 토큰(~6500)"을 계산해 안전한 동시 요청 수를 구한다. Context Length
자체는 최초엔 GUI 팝업으로 물어봤으나, **LM Studio REST API v0
(`/api/v0/models`)이 로드된 모델의 `loaded_context_length`를 그대로
내려준다는 걸 실측으로 확인**하고 `get_lm_studio_context_length()`로
자동 조회하도록 교체했다(팝업 제거, 서버 응답 실패 시에만 8192로 폴백).

### 8. 이미지 크기도, 타일 그리드도 파일마다 자동 계산
전송 이미지는 장변 1024px로 리사이즈해서 보낸다(그 이상은 모델 프로세스가
크래시함, 실측: "model has crashed" 에러). 타일 그리드(cols x rows)는
처음엔 사용자가 매번 숫자를 입력했으나, **`compute_auto_tile_grid()`로
이미지 크기에서 자동 계산**하도록 바꿨다(타일 한 변이 대략 900px가
되도록 각 축을 독립적으로 나눔 - 가로가 세로보다 훨씬 긴 배선도가
많아서 cols/rows를 동일하게 묶지 않음). 폴더 배치 처리도 파일마다 크기가
다르므로 개별적으로 계산한다.

### 9. 결과에서 한글은 완전히 제외
최종 JSON에는 영문/숫자/기호 텍스트만 필요하고 한글 각주/설명 문구는
불필요하다(사용자 지시). `filter_out_hangul()`이 텍스트에 한글 음절/자모가
하나라도 섞인 항목을 통째로 버린다(부분적으로 한글만 지우면
"K-1(계속)" 같은 텍스트가 망가지므로 항목 단위로 제외).

## 작업 흐름 (GUI 사용 순서)

1. **📁 파일 불러오기** — PDF/이미지 로드 (PDF는 zoom=3.0 고해상도 렌더링)
2. **원본 이미지 위 클릭으로 경계점 찍기** — 배선도 윤곽을 따라 계속 클릭
   (Ctrl+휠로 확대/축소, 휠만 돌리면 스크롤)
3. **✅ 경계 완성** — 폴리곤 확정, 바깥 마스킹 + 바운딩박스로 크롭
4. **💾 잘라낸 배선도 PNG로 저장** — 파일명 기본값은 원본 PDF 파일명의
   첫 `_` 이전 부분(도면번호, 예: `A60023104_..._Cable.pdf` → `A60023104.png`)
5. **🔤 3-B. 전체 텍스트 추출** (단일 파일) 또는
   **📂 3-C. 폴더 전체 텍스트 추출** (여러 PNG 일괄) — 자동 타일 분할 +
   병렬 Gemma 질의, 한글 제외 후 `{도면번호}.json`으로 저장

3-C는 사람이 미리 PNG 55장을 만들어둔 폴더(예:
`TestData/PDF_File/Image/`)를 통째로 순회하며, PNG와 같은 폴더에 JSON을
남긴다.

## 모듈/함수 구성 (`template_gui.py`)

| 함수 | 역할 |
|---|---|
| `ask_local_vlm_extract_all_text()` | 이미지 하나를 Gemma에 보내 보이는 모든 텍스트를 `{"text","x","y"}` JSON으로 추출. 1024px로 리사이즈해서 전송, 실패 시 reasoning의 마크다운 목록에서 폴백 회수. |
| `compute_auto_tile_grid()` | 이미지 크기 → 타일 한 변이 ~900px가 되도록 cols x rows 자동 계산 |
| `compute_safe_parallelism()` | Context Length → 안전한 동시 요청 수 계산 |
| `get_lm_studio_context_length()` | LM Studio `/api/v0/models`에서 로드된 모델의 실제 Context Length 자동 조회 |
| `extract_all_text_tiled()` | 이미지를 자동 타일로 나눠 병렬 질의 + 중복 제거, 한 이미지 전체 처리 |
| `filter_out_hangul()` | 결과에서 한글 섞인 항목 제외 |
| `process_image_folder_extract_text()` | 폴더 안 모든 PNG를 순회하며 타일 추출 + JSON 저장 (GUI와 분리된 순수 함수) |
| `mask_outside_polygon()` | 자유곡선(폴리곤) 바깥을 흰색으로 마스킹, 원본 크기 유지 |
| `find_diagram_title`/`crop_diagram_region`/`find_diagram_quadrant`/`split_into_sections` | 자동 검출(참고용, 정확도 낮음) - OCR 제목 찾기 + 섹션 분할. 64개 중 27개 실패 실측됨, 메인 경로 아님 |
| `extract_vector_region()` | PDF 벡터 좌표를 새 PDF로 재작성 - 원본 PDF 대부분이 벡터 정보가 없어 실효성 낮음 |

## 알려진 한계

- **자동 배선도 영역 검출은 신뢰할 수 없다.** OCR 제목 찾기, 밀도 기반
  섹션 분할 모두 도면 레이아웃 편차 때문에 실패율이 높아 수동 곡선
  지정이 메인 경로다. 자동 검출 버튼(1-B/1-C)은 참고용으로만 남아있다.
- **벡터 PDF 추출은 대부분 무용지물.** 원본 PDF가 스캔 이미지라 벡터
  데이터 자체가 없는 경우가 많다.
- **Gemma reasoning을 끄는 방법을 못 찾음.** LM Studio UI 토글도,
  `/nothink`/`chat_template_kwargs` API 파라미터도 이 모델/서버
  조합에서는 효과가 없었다(실측). 타일을 작게 나누는 우회로 대응 중.
- **텍스트 추출까지만 구현됨.** 추출된 텍스트(핀 문자/와이어 번호/
  커넥터명)를 좌표 근접도로 그룹화해 "P1: [핀 목록]" 형태로 묶거나,
  더 나아가 핀-핀 연결 관계(넷리스트: 출발 커넥터-핀, 와이어번호, 도착
  커넥터-핀)를 구성하는 단계는 아직 진행 전(사용자가 "그건 나중에"로
  보류).
- **LM Studio가 꺼져있으면 Context Length 조회가 8192로 폴백**된다 -
  실제 로드된 모델의 값과 다를 수 있으니, 조회 실패 로그가 보이면
  LM Studio 서버 상태를 먼저 확인해야 한다.
