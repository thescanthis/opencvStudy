# 케이블 3D 시각화 파이프라인

PSCD1500(Cable Doctor)에서 다룰 케이블의 배선/커넥터 구조를, 도면(PDF)과
CableEye의 `.tcl` 배선 데이터만으로 3D(`.glb`)로 미리 보여주기 위한
독립 파이썬 파이프라인. 아직 Qt/C++ 앱(PSCD1500 본체)과는 연결되어 있지
않고, `test_output/`에 결과 `.glb` 파일을 생성하는 단계까지 완료된 상태다.

## 목적 (왜 이 구조인가)

케이블을 3D로 보여주려는 이유는 세 가지였다:

1. **실물 케이블과 닮은 형태**로 보여주기 위함 (정밀 실측은 아니어도 됨)
2. **커넥터 핀 구멍 하나하나에 실제로 선이 꽂힌 것처럼** 표시해, 단선·단락·절연저항
   검사 결과를 정확한 핀 위치에 대응시키기 위함
3. **배선이 서로 겹치지 않고 정갈하게** 지나가도록 하기 위함 — 특히 분기(갈래)
   케이블에서, 갈라지는 지점 전까지는 다발 안에서도 각 가닥이 자기 자리를
   지키며 나란히 가고, 갈라지는 지점부터 각자 목적지로 자연스럽게 흩어져야 함

같은 화면 안에서 CableEye의 GFX 뷰(2D 회로도, 장비 연결 시에만 동작)와는
역할이 다르다 — 이 파이프라인은 장비 연결 없이 도면/TCL만으로 미리보기를
제공하는 게 목적이다.

## 데이터 흐름

```
TestData/케이블폴더/{Cable.PNG, Cable.pdf, cable.tcl}
        │
        ├─ cable.tcl  ──▶ tcl_parser.py    (실제 배선 목록: 어느 핀이 어느 핀과 연결되는지)
        │                       │
        │                       ▼
        │                 cable_tree.py    (배선 수를 세어 케이블의 물리적 트리 구조를 복원)
        │
        ├─ Cable.pdf  ──▶ (육안 판독)       (커넥터 규격의 핀 배치 → connector_specs.py에 수동 등록)
        └─ Cable.PNG  ──▶ (육안 확인)       (실물 형태 참고 — AI 추정은 현재 미사용)
                │
                ▼
        cable_shapes.py  (직선/커브/꺾임/포크 중심선을 순수 기하학적으로 생성)
                │
                ▼
   wire_builder.py / tree_cable_builder.py
   (커넥터 UV 배치 + TCL 배선을 중심선에 얹어 셸+배선 3D 메쉬 생성)
                │
                ▼
        결과 .glb (test_output/ 아래)
```

## 케이블 패턴의 원자 단위

여러 형태를 만들어보며 정리한 결론: 케이블 패턴의 원자는 **2개**다.

| 원자 | 정의 |
|---|---|
| **경로** | 곡률이 0이면 직선, 있으면 곡선. 곡률이 크면 "꺾임"으로 보일 뿐 같은 것의 정도 차이 |
| **분기** | 경로가 1→N으로 나뉘는 사건. **재귀적으로 적용됨** |

나머지는 전부 조합이거나 파라미터 차이다:
- **꺾임** = 직선 + 곡률 큰 구간 + 직선 (별도 원자가 아님)
- **S자** = 곡률 부호가 바뀌는 경로
- **N중 분기** = 분기의 재귀 (이중 분기라는 별개 패턴이 존재하지 않음)
- **커브 중간 분기** = 경로 + 분기

이 정리 덕분에 "새 패턴을 계속 찾는" 대신 **분기를 재귀 구조로 만드는 것**
하나로 문제가 좁혀졌고, 그 결과가 `cable_tree.py` + `tree_cable_builder.py`다.

## 핵심 발견과 결정 (시행착오 요약)

### 1. PDF는 스캔 이미지라 좌표를 자동 추출할 수 없다
조사해보니 케이블 도면 PDF는 CAD 벡터 데이터가 아니라 통째로 스캔된
래스터 이미지(`CCITTFaxDecode`)였다. 텍스트 레이어는 사이드바(제목란)
메타데이터뿐이고, 도면 본문(치수·커넥터·핀 배치·결선도)은 전부 이미지
픽셀 안에만 있다. 그래서:
- 실제 배선(누가 누구와 연결되는지)은 `.tcl`이 텍스트 파일이라 정확히 파싱 가능 → **여기는 AI/추측이 전혀 필요 없다.**
- 커넥터 핀 배치(원 안에서 A핀이 어디, B핀이 어디)는 도면 이미지를 사람이 직접 읽어 `connector_specs.py`에 좌표로 옮겨 적었다. OCR/Hough Circle 등 자동화를 시도했으나 스캔 노이즈로 신뢰도가 낮아 포기하고, "라벨 위치를 OCR로 찾아 크롭 → 사람이 읽고 좌표화" 방식으로 정리했다.

일부 도면(A20016147 등)은 예외적으로 판독 가능한 CAD 도면이라 치수를
직접 읽을 수 있었다(트렁크 1800mm, 가지 370/1250mm 등).

### 2. AI(사진 기반 depth/mask)는 목표에 안 맞았다
처음엔 `rembg`(배경 제거) + `Depth-Anything-V2`(깊이 추정)로 케이블 사진에서
외형을 추정했는데, 결과가 울퉁불퉁해서 배선 다발이 서로 겹치고 지저분해
보였다. "형태만 실물과 비슷하면 되고, 안의 선은 정갈해야 한다"는 목표에는
AI 추정 외형보다 **순수 기하학적 곡선(사인 곡선, 직선+원호)** 이 훨씬 적합해서
`cable_shapes.py`로 전환했다. `vision.py`/`geometry.py`(AI 경로)는 남아있지만
현재 사용하는 경로가 아니다.

### 3. 분기는 "포크(Y자)"여야 자연스럽다 — 각진 코너가 아니라
초기 분기 구현은 `bent_centerline`(직선 + 원호 + 직선)을 썼는데, 갈라지는
지점이 각지게 꺾여 부자연스러웠다. 참조 GLB(`Cable_1-2.glb`)를 관찰해보니
실제로 필요한 건 **분기점에서 접선이 부모와 완전히 같은 방향으로 시작해
서서히 벌어지는 부드러운 포크**였다.

`cable_shapes.fork_branch_centerline()`이 그것으로,
`side_amount = (1 - cos(t·π)) / 2` 공식을 쓴다 — `t=0`에서 기울기가 0이라
부모 접선을 그대로 이어받아 출발하고, 뒤로 갈수록 서서히 옆으로 휜다.
(`sin(t·π)`는 `t=0`에서 기울기가 최대라 "직각으로 튀어나오는" 것처럼 보였다.)

### 4. 분기 구조는 TCL에서 자동으로 복원할 수 있다
`.tcl`에는 트리 구조가 직접 적혀있지 않고 점대점 배선(`o@`)만 있다.
하지만 **"두 커넥터 사이를 몇 가닥이 지나는가"를 세면 물리적 구조가 드러난다** —
배선이 많이 지나가는 경로가 곧 굵은 몸통이기 때문이다.

`cable_tree.py`가 이 원리로:
- 커넥터를 노드, 배선 가닥 수를 간선 가중치로 하는 그래프를 만들고
- 가장 많은 가닥이 모이는 커넥터를 루트(트렁크 시작)로 잡고
- 가중치가 큰 간선을 우선 채택하는 최대 신장 트리를 만든다

실제 결과 예:
```
A60025763:  P2 → {P1(3가닥), P3(1가닥), P4(1가닥)}
A20016148:  P1 → P3(6가닥) → P5(3가닥)      ← 2중 분기가 자동으로 잡힘
                → P4(3가닥), P2(1가닥)
```

### 5. 배선의 "다발 안 자리"는 전역으로 한 번만 정해야 한다
가장 오래 붙잡았던 문제. 처음에는 구간마다 "그 구간을 지나는 배선들"만
모아서 원형으로 재배치했는데, 구간마다 지나는 배선 수가 다르다:
몸통 15가닥 → 가지 9가닥 → 끝 3가닥. 그래서 **같은 배선의 자리가 구간이
바뀔 때마다 확 달라져**, 케이블 안에서 가닥들이 서로 자리를 맞바꾸며
빙빙 도는(뒤틀리는) 모양이 나왔다.

해결: 배선마다 각도를 **한 번만** 정하고 모든 구간에서 그대로 유지한다.
반지름도 고정한다(구간별로 다발 굵기를 바꾸면 배선이 안팎으로 들락거려
직선으로 못 간다). 그 결과 다발이 통째로 나란히 흐르고, 자리가 실제로
바뀌는 건 양 끝(핀에 꽂히는 부분)뿐이다.

### 6. 오프셋 보간은 극좌표로 — 원 중심을 가로지르지 않게
(u,v)를 직선 보간하면 배선이 다발 반대편으로 옮겨갈 때 **원의 중심을
가로질러** 지나가 경로가 각지게 꺾인다("네모를 그리며 간다"). 극좌표로
보간해 각도는 최단 방향으로 돌고 반지름만 변하게 하면, 배선이 케이블
단면의 둘레를 따라 부드럽게 옮겨간다.

단, 이 방식은 **각도가 전역 고정일 때만** 유효하다. 각도를 매번 다시
계산하는 구조에서 극좌표 보간을 쓰면, 목적지 각도가 조금만 달라도
직진해야 할 배선이 나사선처럼 빙 도는 부작용이 생긴다(실제로 겪었고
되돌렸다).

### 7. 배선 한 가닥 = 튜브 하나, 조각내지 않는다
배선을 "트렁크 구간 + 가지 구간"처럼 나눠 각각 튜브로 만들면, 두 조각의
이음매가 어긋나 "허공에서 갑자기 시작하는 선"처럼 보인다. 트리 경로
전체(출발 커넥터 → 도착 커넥터)를 통째로 이어 **하나의 연속된 점열**로
만든 뒤 한 번에 튜브로 만들어야 이음매가 원천적으로 없다.

### 8. 4갈래 이상은 평면 부채꼴이 아니라 원뿔로 퍼뜨린다
가지가 여러 개일 때 한 평면에서만 부채꼴로 퍼뜨리면 부챗살처럼 납작해
보인다. 4갈래 이상이면 몸통 축 둘레로 방위각을 돌려가며 원뿔 모양으로
배치해야 실물처럼 사방으로 뻗는다.

### 9. 튜브 메쉬 생성은 자체 구현으로 교체했다
초기에는 `trimesh.creation.sweep_polygon`(shapely 기반)을 썼는데, 경로의
접선 방향이 인접 지점 사이에서 급격히 바뀌는 구간(분기 접합부 등)에서
프레넷 프레임 계산이 0-나눗셈을 일으켜 좌표가 수백 배로 폭발하는 버그를
재현/확인했다. `wire_builder.create_tube_mesh()`를 `_centerline_frames`
(parallel-transport 프레임, 급격한 뒤틀림을 스스로 방지)를 재사용해 각
지점에 원형 단면 링을 직접 배치하고 잇는 방식으로 다시 구현해 해결했다.

### 10. TCL의 예외적인 표기들
- **단일핀 커넥터**: `p@P2@ @B5:33`처럼 핀 이름이 공백(`" "`)인 경우가 있고,
  이때 배선은 `o@P1-A@P2 @...`처럼 하이픈 없이 `"P2 "`로 적힌다. 핀 UV를
  찾을 때 `"커넥터-핀명"` 키와 형식이 달라 배선이 누락됐던 버그가 있었다.
- **핀 수 동률**: P1과 P4가 둘 다 6핀이면 "핀이 가장 많은 커넥터"로
  트렁크를 자동 판별할 때 결과가 불안정하다. 실물/도면상 명백한 경우
  `trunk_connector`/`root`로 명시하는 편이 안전하다.
- **가지끼리 직접 배선**: `o@P3-A@P4-D`처럼 트렁크를 거치지 않는 배선이
  있다. 이것도 물리적으로는 트렁크 다발 안에 있다가 분기점에서 갈라지는
  것이므로, 트렁크 구간을 건너뛰면 안 된다.

## 모듈 구성

| 파일 | 역할 |
|---|---|
| `tcl_parser.py` | `.tcl` 파싱. `p@`(핀 정의), `o@`(실제 배선=Open 검사 대상)만 읽는다. `s@`/`i@`(Short/Isolation 검사 조합)는 배선이 아니므로 의도적으로 무시. |
| `cable_tree.py` | **배선 수를 세어 케이블의 물리적 트리 구조를 복원.** 최대 신장 트리로 "몸통 → 가지 → 그 가지의 가지"를 자동 판별. N중 분기 대응의 기반. |
| `connector_specs.py` | 실제 도면에서 판독한 커넥터 핀 배치 좌표 테이블. 형번(MS3475, D38999 등)이 달라도 핀 배치가 같으면 공용 패턴("18핀 육각형" 등)으로 등록해 재사용. |
| `connector_layout.py` | `layout_pins()` - 알려진 규격이면 `connector_specs`의 실측 배치를, 모르면 균등 원형으로 근사. |
| `cable_shapes.py` | 중심선 생성기. `straight_centerline`, `curved_centerline`, `bent_centerline`, **`fork_branch_centerline`**(접선 연속 포크). AI 없이 순수 기하학. |
| `wire_builder.py` | 2-커넥터 케이블의 셸+배선 생성. `create_tube_mesh`(자체 구현 튜브 스윕), `_centerline_frames`, `_compute_curvature_shrink`(급커브에서 배선이 셸을 뚫지 않게 축소) 포함. |
| `tree_cable_builder.py` | **트리를 따라 재귀적으로 셸+배선 생성. N중 분기 지원.** 전역 슬롯 배정(배선이 뒤틀리지 않게) + 극좌표 보간 + 경로 통짜 튜브. 현재 분기 케이블의 메인 경로. |
| `branching_wire_builder.py` | 1단 분기 전용 이전 구현(A20016147 예시가 이걸로 만들어졌다). `tree_cable_builder`가 상위 호환이지만, 실측 치수를 세밀하게 넣은 예시가 남아있어 보존 중. |
| `new_cables_demo.py` | 신규 케이블 5종을 한 번에 생성하는 스크립트. |
| `shape_prototypes_demo.py` | 형태 원형(직선/커브/꺾임/분기)을 한 번에 생성하는 데모. |
| `curved_split_demo.py` | 커브 중간 지점에서 배선을 두 그룹으로 나눠 새 파이프로 갈라지는 데모(9/8 분할). |
| `extract_connector_crops.py` | PDF에서 "코넥터 핀 후면투영 상세도" 라벨을 OCR(Tesseract)로 찾아 그 주변을 크롭하는 스크립트. 커넥터 규격 조사용. |
| `dataset.py`, `pipeline_controller.py`, `vision.py`, `geometry.py` | AI(사진 기반) 경로의 이전 구현. 현재 메인 경로에서는 사용하지 않지만 참고용으로 남아있음. |

## 남은 작업 / 알려진 한계

- **PSCD1500(Qt/C++ 본체)과 미연결.** 지금은 `.glb` 파일을 만드는 것까지만
  되어 있고, Qt 안에서 이 파일을 열어 마우스로 돌려보는 3D 뷰(Qt3D 등
  런타임 뷰어 통합)는 별도 작업이 필요하다.
- **커넥터 규격 조사가 데이터셋 전체를 커버하지 못함.** 106개 케이블 중
  일부만 규격을 확보했고, 매핑되지 않은 케이블은 균등 원형 근사로
  fallback된다(동작은 하지만 실제 핀 배치와 다를 수 있음).
- **가지 각도/길이는 대부분 균등 근사.** `segment_lengths`로 가지별 실측
  길이를 받을 수 있지만, 도면에서 값을 옮겨 적는 작업은 케이블마다 별도로
  필요하다(A20016147, A20016148 정도만 시험 반영).
- **트리 루트가 실물과 다를 수 있음.** `cable_tree`는 "가닥이 가장 많이
  모이는 커넥터"를 루트로 잡는데, 예를 들어 A60025763은 실물 사진상 P1이
  몸통 시작이지만 P2가 루트로 잡힌다(P2가 분기점이라 가닥이 가장 많음).
  트리 구조 자체는 동등하나, 실물과 정확히 맞추려면 `root`를 명시해야 한다.
- **37/55핀 벌집형 좌표는 근사치.** 정밀 검사가 필요해지면 고해상도
  재판독이 필요하다.
- **커넥터 자체의 3D 형상이 없다.** 지금은 셸(케이블 피복)과 배선만 그리고,
  커넥터 몸체(원형 하우징, 나사산 등)는 표현하지 않는다. 관련 도면/이미지
  데이터가 없어 보류 중.
